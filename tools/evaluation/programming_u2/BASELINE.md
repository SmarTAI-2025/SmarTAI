## 已复现的现有缺陷

| ID / 归属 | 最小复现与实际结果 | 修复后的关闭条件 |
|---|---|---|
| D01 / 新增三（编辑执行一致） | 函数用例 `function_args=[0], expected_return='0'`；原编辑框改为输入 `[5]`、期望 `5` 保存。请求只改 `input/expected_output`，旧函数字段保留；刷新仍显示 `[0]/0`，真实 SQLite 和批改输入也保留旧值 | 同一现有入口编辑后，显示、保存、刷新、恢复及真实执行输入/预期一致；保留来源与函数身份 |
| D02 / 新增一、三（合同校验） | PUT `test_cases=[{function_name:'fib',function_args:'not-a-list',expected_return:1}]` 返回 200 且原样入库；随后实际 `ProblemInfo` 校验失败 | 保存前拒绝无效合同且不改变版本/内容；有效函数/stdin 值完整保存 |
| D03 / 新增一、09（空预期语义） | 真正比较逻辑中，预期 stdout 为空、固定进程输出 `UNEXPECTED`，仍计 1/1 通过 | 明确区分“预期空输出”与“未提供预期”；前者必须比较，后者不得冒称执行验证通过 |

D01 有浏览器请求、刷新截图、真实 HTTP/数据库和 adapter 输入交叉证据；仍未启动真实 OCI。D02 与 D03 也只描述本次实际覆盖的层次。实现修复均交同学，U2 原样复测。
