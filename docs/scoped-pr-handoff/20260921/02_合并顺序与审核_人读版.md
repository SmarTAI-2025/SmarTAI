## 每次只重复四步

1. 确认前一项已经合进 main，再打开下一项；第一项 #80 没有本链前置。
2. 点 PR 标题旁 Edit，把 base 从前序功能分支改为 **main**。只改 base，不重写代码、不 rebase、不 force push。确认 Files changed 只剩本功能，且无冲突。**不要对还指向父功能分支的 PR 直接点 Merge**，否则合进的是父分支，不是 main。
3. 核对最新检查与最终 HEAD，完成仓库要求的至少一个合格非作者正式批准；有真实未解决讨论先解决。改 base 后 GitHub 可能重新运行检查／重新要求审核，应以页面当前状态为准。
4. 选择 **Create a merge commit** 并确认。不要 Squash/Rebase，不要把后续 PR 的父分支提前删除；至少等子 PR 已切到 main 后再考虑清理旧分支。

原作者历史已保留，每个功能会再有自己的 PR merge 记录。base 选择不改变本地检出的代码文件，但会改变 diff、合入目标和组合验证。原来先用父层作 base，是为了清楚显示本层；父层合入后改为 main，是为了把这层真正送到主干。
