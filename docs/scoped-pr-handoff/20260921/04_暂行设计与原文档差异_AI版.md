## 03A: actual schema and invariants

One AssignmentQuestionRecord/q_id/max_score is one scored major question. Versioned structure is stored in source.presentation.question_structure and projected as optional API metadata. The major stem and max_score remain authoritative. Subpart IDs sp1/sp2 are scoped metadata, not independent grading identities. q_id is not promised globally permanent across arbitrary re-extraction.

MajorQuestionStructureV1 retains major_number, major_order, shared_stem, subparts(label/order/stem/type_hint/source_span_ids), structure_source and review_status. No leaf score columns, group allocation API or independent subpart skill dispatch were added. Explicit rubric allocations are validated against the sole major maximum using Decimal; free-text/percentage rubrics keep existing compatibility. This is not a full structured teacher scoring-outline pipeline.

Old 03A §§1.3,5.1–5.3,6.1–6.4,7.1–7.3 describe ScoringGroup/GradingLeaf flattening and independent leaf scores. The approved current implementation in #62/#63 instead retains a single scored major/editor and internal subparts. Do not synthesize q1a/q1b or duplicate the major maximum. Preserve full shared conditions, reference/rubric labels, teacher authority, owner/revision/busy gates and legacy flat records.

The #62 fixes protect empty extraction candidates from dedup crashes and reject textual dedup across distinct explicit numeric/dotted major labels before overlap/containment. Unnumbered fragments and contextual subparts keep existing rules. f(a), f (a)=... and ordinary inline expressions are not automatically headings. The parser is conservative metadata extraction, not a general mathematical parser.

#65 persists/reuses per-major artifacts and stage checkpoints. Preserve input/provider fingerprints, order, structure, score policy, lease token, attempt and workflow revision. ## 10 and knowledge lifecycle

Completion cleanup requires a matching formal finalization OR grading completion generation, AND recoverable persisted inputs. source_retention.completion_inputs_are_recoverable checks run ownership, frozen question/revision set and answer-row coverage, and relevant latest recognition outcomes including archive relationships. A genuine empty-answer placeholder is not a missing persisted row. Legacy paths remain compatible; do not invent new mandatory evidence fields for old complete records.

#66 checks at enqueue and again in worker authorization. OCR/unresolved source failure retains necessary bytes. Pure grading failure can retire originals when saved inputs suffice. Replacement cleanup is separate: verified bytes must be atomically adopted before old-byte retirement; a failed upload attempt never authorizes deletion. Explicit task deletion is another owner-authorized path. Ordinary completion does not delete structured results or retained knowledge.

#67 task_only cleanup occurs after the last task reference; promotion to retained is monotonic. Failed physical deletion remains charged and retryable. Old10 §B3's finalization-only trigger is overridden; tombstones, ownership, generation fencing, truthful state and no-data-loss remain binding.
