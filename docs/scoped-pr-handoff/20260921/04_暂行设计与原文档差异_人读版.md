# 当前暂行设计与原附件的明确差异

本次拆分只改变 PR 组织，不撤销负责人在 2026-09-20/21 对功能方案的选择。原附件保持历史原文，不通过悄悄改附件来伪称原要求全部实现。其余 owner 隔离、不丢数据、教师分值权威和错误如实呈现要求仍有效。

## 03A：一道大题是唯一处理单位

当前 #62/#63 保留一道大题一个 `q_id`、一个 `max_score`、一个数据库计分记录。`(a)/(b)` 等是该大题内部内容与 metadata，不是独立评分行。参考答案、rubric、生成、恢复都随大题处理，纯小问不会额外复制满分。

与原 03A §1.3、§5、§7 不同：没有分别给每个 leaf 分配分数，没有 `question-groups` 原子组更新 API，没有每个小问一张计分卡或独立技能调度；有显式分项分值时，校验的是大题 rubric 分项合计。不能在完成报告中说已经实现原 group/leaf API。

始终不变：`1.1`、`1.2` 是两个完整大题号，不能仅因点号前缀或正文相同而合并；`1.1(a)/(b)` 保留所属大题与标签；函数 `f(a)` 不是小问标题。#62 的新增回归保护了这些实质正确性。

后续 07 的一对一映射需按当前结构适配：不同小问的答案块可归入同一大题，并保留标签和来源；不能后块覆盖前块，也不能创建 q1a/q1b 再把大题总分重复相加。缺父级上下文和重复同标签答案仍须明确留问题，不猜。

## 03B／03C：按大题生成和恢复，继续 BYOK 并发

与原 03B §5.1 的 leaf 单元／专用 1–2 上限不同，#64 使用一大题一个生成单元，有效外层并发为 `min(BYOK max_concurrent, endpoint 上限)`；provider 内仍有并发和 RPM 门禁。#65 的 artifact/checkpoint 也按大题，不按旧 leaf 拆开。

调整位置：`backend/agents/question_preparation_agent.py::_major_question_generation_concurrency`；BYOK `ProviderConfig.max_concurrent/rpm`；`backend/config.py::max_concurrent_llm_per_endpoint`；底层限制在 `backend/llm/providers.py`。不新增另一套题目专属配置。endpoint 限制是当前进程内保护，不冒充跨部署实例的统一厂商配额。

提高并发可减少等待，但不保证质量更好，也不保证一直更快；厂商限流、超时和资源峰值都可能抵消收益。后续应根据真实请求时延、峰值、RPM和错误率调整，而不是临时绕开限制。

## 10：按可恢复性决定完成清理

原 10 §B3 只允许最终确认后的清理；负责人已接受批改完成或最终确认均可触发。#66 额外检查所需结构化题目／作答是否完整、相关识别是否仍需原件重试；仅终态状态不够。队列建立时和实际删除前均检查。

识别失败需要重试的原件／必要压缩容器保留；纯批改失败但可由完整结构化输入重试时可清。新件成功保存并原子替换后，旧件可以立即进入清理；仅仅开始上传或新件保存失败，不授权删除旧件。物理删除可能异步重试，不把排队当作已删除。

普通完成清理不删除结构化题目、作答、结果和长期 retained 知识库对象。用户主动删除任务是另一个明确授权的生命周期，不能与普通清原件混写。#67 的 task_only 在最后任务引用移除后清理，retained 保留语义仍在。
