## 03A actual representation

One `AssignmentQuestionRecord` is one scored major question. Existing q_id identifies that record within the prepared question package. A q_id is not a globally permanent identity across arbitrary re-extractions. Generated subpart IDs (sp1, sp2, ...) are metadata identifiers scoped to a major/package, not grading IDs.

Representative shape:

```json
{
  "q_id": "q1",
  "number": "1.1",
  "max_score": 20,
  "stem": "Shared conditions. (a) Compute... (b) Prove...",
  "question_structure": {
    "contract_version": 1,
    "scoring_unit": "major_question",
    "major_number": "1.1",
    "major_order": 0,
    "shared_stem": "Shared conditions.",
    "subparts": [
      {"subpart_id":"sp1","label":"(a)","order":0,"stem":"Compute...","type_hint":null,"source_span_ids":[]},
      {"subpart_id":"sp2","label":"(b)","order":1,"stem":"Prove...","type_hint":null,"source_span_ids":[]}
    ],
    "structure_source":"deterministic",
    "review_status":"confirmed"
  }
}
```

Storage uses `source.presentation.question_structure`; API projects `question_structure`. Authoritative stem/max_score remain the scored record. `rubric_point_summary` is derived display/validation data, not another score authority. Absence of recognizable explicit subpart allocations stays compatible with free-text/percentage rubrics; once explicit allocations are recognized, completeness/duplicates/Decimal exact sum are checked.

The example is illustrative, not a claim that external recognition span IDs are populated by this integration. Mixed component types can produce major type “其他”; no per-subpart skill dispatch is added. The teacher retains editable complete reference/rubric.

## Retention policy20260920

Raw originals are separate from structured inputs/results and retained library bytes.

Completion authorization is two-phase: (formal-result generation matches OR grading completion generation matches) AND persisted inputs remain recoverable. At enqueue, candidate original IDs are bounded; at worker claim, generation and recoverability are rechecked. A terminal run status alone is insufficient.

Recovery evidence includes the exact frozen question IDs/revision set and complete answer-row coverage, plus latest source-outcome status for candidate files and their source containers. A genuine empty-answer row is not missing persistence; an absent row/revision is. Parsed status is not interchangeable with partially_read, pending, parse_failed, identity_conflict or no_matching_answer.

For partial grading failure, if every input is already structured and the failure was at grading, originals may retire; retries use saved input. Recognition failure protects source/necessary archive. New validated atomic replacement authorizes old-source retirement even if old recognition failed. Failure before new-source adoption leaves old current data available. Explicit task deletion has independent owner authorization and can remove task structures/results as originally implemented; ordinary completion cleanup cannot.

Knowledge: task_only retention ends after last task reference disappears; retained is monotonic and survives task detach/delete while a retained library object exists. Failed physical deletion remains charged, retried and accurately projected.

Old10 §B3's exclusive finalization trigger is overridden; its tombstones, metadata, owner/file/revision identity, no silent missing-object success, failure retry and exclusion of retained/structured data remain binding. Later source-generation changes must not let an old completion manifest delete a newly uploaded file.
