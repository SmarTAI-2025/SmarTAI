# 当前暂行设计：与原实施附件的明确差异

决策人：项目负责人 gsy。决策来源：本次对话的明确指令（2026-09-20）。不是由 GPT 擅自把旧要求改成已完成。

适用范围：整合分支 `fix/verified-integration-20260920`，代码提交 `3977108642ce23fbbd149326c8e8df6d9c8ba6cf`。未来改动应另记新的决定，不能把旧附件和本文件混着执行。

## 03A：一道大题是一个真正处理单位

现在采用：

```text
大题1.1：q1，满分20
  共用题干
  (a) 计算……
  (b) 证明……
  一份完整参考答案、一份可编辑评分标准
  生成一次；恢复一个完整单元；批改一次；总分只计20

大题1.2：q2，满分10
  同样独立处理
```

`(a)/(b)` 不是两道另计满分的题，不各自得到 q_id。老师仍可在完整评分文字中写 `(a)8分、(b)12分`，系统对能明确识别的分项做合计校验，但这不等于后台有两条独立计分记录。

| 原03A附件 | 当前暂行方案 |
|---|---|
| §5.1 ScoringGroup 下有独立 GradingLeaf | 一道大题一个 AssignmentQuestionRecord；小问只是内部结构 |
| §5.2 每个 leaf 有 q_id、leaf_max_score | q_id/max_score 只属于大题；小问没有独立满分字段 |
| §6.2/6.3 各小问独立分类、分值分配 | 整道大题一起处理，混合题型可能按“其他”处理 |
| §7.2 原子 question-groups 分配接口 | 原有大题编辑＋rubric 分项合计校验，没有新增组分配接口 |
| §7.3 每 leaf 批改，再按组小计 | 每大题批改一次，现有题目总分相加，不再重复算父题 |

这是为了尽快把现有成果稳定合入的暂行取舍，不宣称旧附件的 leaf 功能已经实现。后续依据真实反馈决定是否拆小问独立处理；不能让07或09自己偷偷引入第二套题目模型。

需要保留的规则没有变：`1.1`、`1.2` 默认是两个完整大题号；数学函数括号不是小问标题；题干、标签、来源和教师满分不能错配或丢失；旧任务没有结构字段时继续兼容。

## 03B：复用模型自身的并发配置

原03B §5.1 要求 `SMARTAI_QUESTION_GENERATION_CONCURRENCY`，只允许1～2；现在不新增该配置，继续采用：

```text
有效大题并发 = min(所选 BYOK 的 max_concurrent, endpoint 安全上限)
```

provider 的 RPM 限制继续生效；任务启动后使用已冻结的配置，不因单题失败静默换模型。每个大题的答案和评分依据在同一个生成请求中处理，最终按原题号顺序发布。进度 x/y 的分母是大题数，不是小问数。

后续调哪里：先看所选 BYOK 记录的 max_concurrent/RPM；再看 `backend/agents/question_preparation_agent.py` 的并发解析及 `backend/config.py` 的 endpoint 上限。provider 层仍负责请求级 semaphore/RPM。不要在页面另加一个与后台不一致的并发字段。

更多并发在额度和资源允许时可能缩短等待，但不保证答案质量更好；过高会增加限流和重试。暂不为主观性能优化改设计，先收集请求数、限流、延迟和失败率再调整。

## 03C：恢复的也是大题

原03C §5.3要求按leaf保存artifact；现在保存和恢复一个完整大题的题干、标签、教师满分及生成结果。成功的大题可复用，未完成的再处理；来源/provider/hash/attempt/lease/revision核验保持。

没有新增恢复页面，也没有恢复成“上传后先逐题审核再生成”。全套准备完成后，老师仍只在原有最终页面统一复核。

## 10：清理时机改为“是否还需要原件恢复”

原10 §B3唯一允许 finalization 后清理。现在明确接受：最终确认或批改结束都可触发，但不能删除仍需重试的唯一原件。

| 情况 | 当前行为 |
|---|---|
| 上传后识别失败，需要重试 | 保留原件和安全错误，不要求用户重新上传 |
| 压缩包有成员仍识别失败／未确认 | 保留相关来源及必要的外层容器 |
| 批改 partial_failed，但冻结结构化题目和作答齐全 | 可以清理当次原件；批改重试复用结构化输入 |
| 冻结题目、submission revision或答案行缺失 | 不安排完成清理；已排队但未开始的清理重新核对并恢复可用状态 |
| 新文件只开始上传，保存／采用失败 | 不因这次失败尝试删除旧文件 |
| 新文件已保存并成功替换当前来源 | 旧文件可尽快清理，不受旧识别失败阻止；新文件不能误删 |
| 用户主动删除任务 | 走独立、经过owner鉴权的任务删除流程，不与普通完成清理混淆 |
| 资料库 retained 文件 | 不随任务完成清理；task_only 在最后任务引用移除时按其独立规则处理 |
| storage删除失败 | 仍记实际占用并自动重试，不假报删除成功 |

这里保留的是恢复所需内容，而不是无条件永久保留所有历史原件。批改结束后可能已经无法再预览当次原始PDF／图片，这属于本次明确接受的产品行为；结构化结果仍需保留。未来若教师反馈需要“批改后原件复核窗口”，应另定保留策略。

## 05/06/07/09 接手人尤其注意

共享识别只保留题号、标签、页码/span和内容，不自己决定计分身份。06给大题附证据；07将同一明确大题的不同小问片段保留标签后组织成该大题的一份作答；重复或含糊片段不能后写覆盖前写。09按大题 q_id 计分一次，并继续区分未执行和真实0分。

上述是后续接口要求，不是说本轮已经完成共享多模态、顺序无关映射或正式OCI评分。旧文件作为历史需求保留，交接时必须把本文件一起发送。
