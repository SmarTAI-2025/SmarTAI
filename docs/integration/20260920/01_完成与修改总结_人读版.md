## 本轮采用的方案

按项目负责人本次明确决定，继续采用「一道大题一个 q_id、一个满分、一个生成／恢复／批改单元」，小问保留在题干、答案、评分文字和结构 metadata 内；继续复用 BYOK 并发／RPM 和 endpoint 安全上限。没有改回旧附件的独立 leaf 方案，也没有新增固定 1～2 并发开关。具体差异和后续开发约定见《03_当前设计与原文档差异_人读版.md》。

清理规则采用「完成可以清；需要原件重试则保留；成功替换后旧件可清」。这里的成功替换是新文件已保存并被当前任务原子采用，不是刚选中文件或刚开始上传。后台尽快清理不等于不等待保存成功就立即物理删除。

## 实际修了什么

| 修复 | 用户会感受到的变化 |
|---|---|
| 数学括号不当小问 | `f(a)`、`f (a) =`、`g(1)+g(2)` 不再生成假的小问结构 |
| 扣分不增加满分 | `(a)4分，漏步骤扣1分；(b)6分` 按 10 分而非 11 分校验，前后端规则一致 |
| 编辑后结构不残留 | 题号、题干、顺序变化时不沿用不相符的旧结构；其他来源信息仍保留 |
| 首个小问资料标签 | 合并 `(a)/(b)` 时，第一个小问的参考答案和评分标准不再漏掉 `(a)` |
| 进度所有权 | 重复领取失败不删除合法运行者的进度；旧 worker 结束不删除新 worker 的 reporter |
| 密码找回时序 | 匿名响应先发送，再做账号查询和 SMTP；未知账号不会因为跳过发信而暴露明显的同步等待差异 |
| PDF 取消及超时 | 取消发生在创建进程或读取期间，都先终止、排空、回收子进程，再释放并发槽 |
| 原件重试保护 | 尚需识别重试的文件及其压缩包不被完成清理带走；缺失冻结结构化输入时也保留 |
| 成功替换旧件 | 旧文件识别失败不妨碍成功替换后的回收，新文件必须保留 |
| 生产宿主执行保护 | production 下禁止旧路径在网站宿主运行不可信代码；后端明确投影未执行失败，不能冒充学生测试失败 |
| 错误日志 | 批改服务只记录安全错误码与异常类型，避免原始异常 traceback 泄露内容 |
| 依赖安全 | 修正前后端已发现的依赖漏洞版本范围，并验证干净安装；详见 AI 版依赖记录 |

首个小问标签、PDF 回收和生产宿主执行保护是本轮继续检查发现的事项，不是仅重复上一份审计报告。

## 有意保留的限制

密码重置采用现有进程内响应后任务，不新建持久邮件队列。进程在投递前退出可能丢失这次发送，用户需在冷却后重新申请；不宣称「请求成功等于已投递」。

生产环境的旧宿主执行被禁止是安全修复，不是任务 08/09 已完成。正式 OCI 未接通时，不能宣称编程题已经运行；不能通过把生产环境标成 development 来规避保护。

资料库 `retained/task_only` 是存储生命周期能力，不是 06 的共享识别接线。05–09、12、13 的整项工作没有被本轮整合「顺便完成」。
