### Q: major question structure

- `_is_subpart_marker` prevents identifiers/function-call arguments and operator-followed parentheses from becoming headings. It is a conservative metadata parser, not a general mathematical parser; the authoritative stem is not rewritten.
- `_parse_allocations` excludes deduction/penalty prefixes before summing available points. It retains Decimal exact-sum, duplicate and incomplete checks.
- `_labelled_subpart_text` and `_label_first_subpart` preserve the first subpart's label on stem, criterion and uploaded reference before collapsing major rows. Prefix checks replace a weak substring-in-first-characters check.
- No new leaf IDs, group allocation API or leaf score columns are introduced.

`frontend/app/src/lib/rubricPoints.ts` uses the same penalty-prefix rule and integer hundredths. `rubricPoints.test.ts` adds Chinese/English deductions and component allocations.

### P: progress ownership

`tracker.remove_reporter(job_id, expected=instance)` conditionally removes the exact owned reporter under the registry lock; callers without expected retain intentional unconditional semantics (e.g. task deletion).

### A: password reset timing

`request_password_reset(..., delivery_scheduler=None)` retains synchronous compatibility for direct service callers/tests. The HTTP route supplies `BackgroundTasks.add_task`.

Anonymous normalization/domain/hashed email+IP budget runs before scheduling. Every accepted allowed address schedules the same callback shape. Account lookup, raw token generation and SMTP occur in `_deliver_password_reset` after response; only eligible accounts receive email. A delayed attempt that predates `auth_invalid_before` or has expired is discarded. Pending/sent/failed token state, newest-successful-wins, row locking and atomic password/session invalidation remain.

`test_password_reset_deferred.py` calls the ASGI application with a recording send function, asserting response body completion precedes account processing for active/inactive/missing accounts. This is an ordering proof, not a timing-threshold benchmark. A stale deferred attempt cannot mint a link after password change.

This is a response-background task, NOT a durable outbox. Crash-before-send can lose a delivery attempt; no plaintext token is persisted in a queue. Existing SMTP timeout/threadpool limits remain. Do not invent exactly-once email guarantees or claim delivery from a neutral 202.

### F: file lifecycle

`source_retention.completion_inputs_are_recoverable` is a read predicate inside existing workflow-locked transactions; it adds no tables or new lock order.

It checks:
1. run owner/assignment identity;
2. valid owned frozen setup, unique nonempty question IDs, or legacy persisted questions;
3. frozen submission revisions exist and exactly match manifest revisions (legacy count checked when positive);
4. revisions belong to this assignment;
5. each revision contains all required structured answer rows (a real missing-answer placeholder can have empty content; an absent row cannot pass);
6. latest source outcome per stored file is parsed for every relevant source; missing/failed/unresolved source outcomes retain originals;
7. archive relationships are followed via operation artifact_refs/checkpoint container_file_id, not filenames; a failed member protects its source container.

`enqueue_finalized_source_cleanup_in_session` invokes this predicate before marking candidates cleanup_pending. `_cleanup_generation_authorized` retains the approved formal-finalization OR grading-completion trigger, then rechecks recoverability. Existing worker restores untouched rows on supersession and reconciles already-started deletions truthfully.

Replacement cleanup and explicit task deletion are separate authorization paths, intentionally not blocked by failed recognition. Replacement means a verified new stored source has been atomically adopted, never merely an upload attempt. `retained` knowledge objects are not task-original cleanup targets.

New tests cover failed/missing/unresolved source outcomes × direct/archive, latest parsed retry, queued cleanup after lost structured inputs, failed-old-source replacement preserving new source, malformed setup and missing frozen revision. Three new PostgreSQL tests exercise the same semantics on real PostgreSQL.
