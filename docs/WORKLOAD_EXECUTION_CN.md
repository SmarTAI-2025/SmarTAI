# 长任务排队、停止与 AWS 并发配置

2026-10-05 候选实现；本轮没有部署或修改 AWS 配置。下面的新变量须在部署包含本次改动的版本后使用。

## 配置总运行名额

已通过 SSH 核实 `smartai.service` 使用 `/etc/smartai/smartai.env`。在该文件中设置：

```dotenv
SMARTAI_WORKLOAD_MAX_IN_FLIGHT=2
```

这是题目识别、作答识别、资料导入、AI 补全和批改**共同使用的总名额**。例如改为 `4`，服务器最多同时运行四个此类任务，但同一个用户始终最多运行一个，其余自动排队。变量必须为正整数；更新环境文件后重启 `smartai.service` 生效，所有后端进程应使用一致的值。

新任务工作器统一读取此变量；旧 `SMARTAI_WORKFLOW_MAX_IN_FLIGHT` 和 `SMARTAI_MAX_CONCURRENT_JOBS` 不再分别限制这些持久化任务。模型 RPM、每个模型的请求并发及文件处理资源限制仍独立生效，运行名额不等于模型请求数或在线人数。

当前服务器为 2 vCPU、约 2 GiB 内存。默认 2 是保守起点，未做真实大文件并发压力测试，不能视为最大承载人数。扩容前后以实际文件处理内存、CPU 和任务等待时间校验配置。

## 用户看到的行为

- 自己已有任务运行：显示“你已有任务正在处理，本任务排队中”。
- 服务器名额不足：显示“服务器繁忙，本任务已自动排队”。
- 成功提交的任务由数据库队列和服务器工作器持有；关闭页面、退出登录不会撤销任务。登出只撤销登录会话，任务所需的教师配置由服务器加载。服务或上游发生错误仍会进入相应恢复流程，不承诺所有任务必然成功。
- “停止运行”可停止排队或运行，保留配置、原文件及已保存结果；作答识别和题目准备复用既有恢复入口，批改继续复用成功结果，辅助资料任务复用保存的候选结果。
- “继续处理”由用户主动触发，无须重新配置；按这次提交的时间重新排队，不保留第一次提交的位置。输入之后被修改时，旧停止页面不能直接应用过期结果。
- 已发出的模型请求可能仍会计费。停止撤销执行租约并取消服务器协程，阻止后续请求及过期结果写入；不宣称能撤回已到达服务商的请求。

## 有限重试

单次调用最多尝试 3 次，**包含第一次**。限流默认等待约 65 秒加少量随机延迟；尊重更长的 `Retry-After`。一次等待超过 90 秒或累计等待超过 180 秒时提前停止，不截短服务商给出的等待时间。旧的额外六次尝试设置不再扩大预算。

同一运行内，模型耗尽限流尝试后，后续环节不能重新给它一套预算；持久化批改也不再用整题重试放大调用次数。用户手动继续或重试开始新一轮预算。

只有明确的日额度或余额/配额耗尽证据才立即停止。普通 429 不推断为日额度；502/503 等上游故障也不当作限流展示。前端显示尝试次数、等待倒计时及停止入口，额度恢复后由用户主动重试或切换模型，不自动等待到第二天。依据：[OpenAI 错误代码](https://developers.openai.com/api/docs/guides/error-codes)、[429 处理说明](https://help.openai.com/en/articles/5955604-troubleshooting-api-rate-limits-and-429-errors)。
