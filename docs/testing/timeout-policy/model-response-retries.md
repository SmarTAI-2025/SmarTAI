# 单次模型响应 180 秒与有限超时重试

此变更基于 main `e148cd82e50261209ad312b7f84ae43776c31d37`，独立于共享 429 冷却及参数学习工作。不包含 PR300、PR302，也不代表已合并或部署。

## 时间与次数

| 范围 | 本次行为 |
|---|---|
| 后台模型完整响应 | `settings.llm_timeout=180` 秒，每次准入、发送前授权完成后开始计时 |
| 等待发送间隔、模型/端点/主机并发名额 | 不计入单次响应时钟；仍服从所属工作流截止及用户取消 |
| 题目、作答、批改、资料库总时限 | 继续分别为 2.5、3.5、3.5、2 小时 |
| 超时、429、已有结构化格式修复 | 共用现有最多 3 次尝试，包含首次，不叠加重试层 |
| 纯超时重试 | 不增加独立等待，不计入端点过载熔断；重新经过正常发送间隔与并发准入 |
| 已有 429 冷却 | 超时重试同样受正常准入控制；共享截止时间及动态学习由独立工作交付 |
| Ask、资料库查询改写 | 原有单次 60 秒保留，接入相同的有界超时/429重试；查询改写的响应时钟也排除内部排队 |
| BYOK 文本/图像验证 | 不改验证入口、重试或 60/75 秒限时 |

源识别策略名更新为 `source-response-180-v1`。旧名称仍能读取，但在当前产品入口归一到新的 response-only 策略；没有改写保存的历史证据。

百度文档 OCR 不是生成模型：产品源识别调用沿用共用策略，因此该次完整云端识别受 180 秒约束；适配器独立调用的 600 秒兜底、单个网络步骤 30 秒和查询间隔 5 秒保持。已提交的异步任务不因等待超时重新 POST；原有可安全查询/网络步骤的有限重试保留。没有将所有名称含 600 的限时统一替换。

## 重试归属与不确定性

- 普通文本与结构化请求继续使用 `structured_llm` 的现有重试入口；视觉识别、定位、复核、保留的 OCR 转写、Ask/分析与资料库查询改写接入同一套次数/等待控制。
- Provider 和 SDK 不新增内层重试，SDK 的 `max_retries=0` 保持。一次超时后重新调用 Provider，才能重新经过已有发送准入。Provider 的单次方法及代理/中转协议不各加一套循环。
- `ResponseDeadlineScope.authorize_timeout_retry()` 只授权下一次尝试。它不调用 `rejected()`，不清除已发请求的不确定标记；后来的明确 429/认证拒绝也不能否定前次超时可能已计费。
- 识别的发送前持久化授权与逻辑调用预算仍只建立一次，跨最多三次尝试保留。成功取得最终内容后可以采用该结果，但整个逻辑调用的输入/输出 token 置为未知，不能把最后一次响应的 token 当成全部费用。识别的调用预算和 dispatch 计数沿用逻辑调用语义，不是厂商账单或物理请求计数。
- 全部尝试失败、排队中取消或进程中断时，原有不确定提交恢复保护继续有效。显式不可重试、额度耗尽、工作流总截止及用户取消不能获得新的模型重试权限。
- 超时分类只读取当前异常及显式 cause；不把此前请求的隐式 exception context 当作本次 429。真实成功响应的资源回收继续由现有独立清理机制处理，不因关闭异常重新提交。

## 离线验证

新增 `backend/tests/test_model_timeout_retries.py` 覆盖：

- OpenAI、Anthropic、Gemini 直连/代理及三种中转协议的真实适配器路径，使用本地 SDK/HTTP 替身。
- 超时两次后成功、连续超时、超时/429混合、与格式修复共享三次上限。
- 每次重试重新准入、遵守发送间隔，连续超时不触发整组熔断。
- 题目、作答、标答、评分标准、测试资料与资料库识别恢复成功后的内容和未知用量核对。
- 取消排队重试、明确不可重试错误、发送前授权只执行一次及超时后的不确定提交标记。

同时运行既有 Provider 关闭/取消、响应截止、识别持久化、题目准备、查询改写及工作流测试。准确提交的测试数量及 CI 状态见 PR；测试替身不代表真实模型内容准确性或生产性能。没有调用真实模型、使用学生数据、合并或部署。
