## 业务配置管理

详细格式、计量及兼容规则见 [ADMIN_BUSINESS_CONFIG.md](ADMIN_BUSINESS_CONFIG.md)。只接入已经存在的业务限制，不展示部署连接、秘密、运行并发或超时。

- 注册域名：根域名连同子域名按完整标签边界匹配，并进行大小写/IDNA 归一；空字符串明确拒绝全部，`*` 明确允许全部。待验证的申请在完成验证时按最新规则检查，已注册用户不被自动封禁。未设置数据库覆盖时沿用原环境行为；开始后台管理域名后，旧用户找回密码独立于注册准入，以免调整域名造成失联，恢复继承也不撤销这项保障。
- 邮件：复用既有邮箱/IP 窗口计数，默认冷却 60 秒、每邮箱每小时 5 次、每 IP 每小时 20 次。注册与重置沿用各自的记录；修改不重置次数或已发链接有效期，零值不代表无限制。反向代理的真实客户端地址须由可信网关配置，不能信任任意来访者伪造的转发头。
- 存储：未完成任务原件、个人知识资料两个既有持久化账本，包含占用与预留；默认各 512 MiB。优先级为用户覆盖 → 全局数据库覆盖 → 部署环境/代码默认。0 阻止净新增占用；降低额度不删除旧数据，允许查看、清理及既有知识对象复用；新预留仍执行原有净额校验。删除覆盖值表示恢复继承。
- 每次业务事务读取提交后的配置，进程内不缓存；保存后的新检查生效，已经通过准入的操作可能完成。版本校验防止并发覆盖，幂等编号处理网络重试，保存人、原因、时间、前后值写入审计。
- 模型共享池日请求/估算 token 及历史 Ask 额度仍只读：当前计数按进程，尚不能视为可靠跨进程总预算。没有借配置功能开放共享模型池。
- 正常或拉黑销户级联删除该用户覆盖；全清空删除全局覆盖、用户覆盖和域名管理状态，恢复部署初始规则。初始规则若本就关闭注册，清空不擅自放开。

## 身份、密码与会话

- “停用”指停止新建、上传、识别、批改和修改；GET 历史浏览仍允许，历史批改任务保留。已有运行任务不因只读操作被撤销。没有再引入含义重叠的“仅查看状态”第四种状态。
- 密码修改与成功完成忘记密码重置：全部访问令牌和刷新会话失效，当前设备也需重登。单纯发送重置请求不撤销登录。管理员看不到用户原密码/新密码/重置凭证。
- 会话主动撤销、禁止登录、角色变化、开始销户：立即撤销旧登录；不会因恢复账号使旧令牌复活。
- 最后一个有效管理员及自身管理权限受服务端保护。PostgreSQL 管理锁先于用户行锁，事务中重新验证操作人，避免两个管理员同时撤掉对方后无人可管理。
- 管理员 guard 区分 401、403、网络/5xx：失效回登录并保留原地址，网络错误可重试，角色不符显示拒绝。私有/公共 Cookie 名和本地 token 存储名不同，JWT 不放入跳转 URL。
- 拉黑邮箱按现有 `normalize_email`（去空白及大小写归一）精确匹配，不扩大到域名、IP、设备或邮箱别名推断。请求注册仍保留匿名中性反馈，验证阶段拒绝封禁身份。当前未提供拉黑邮箱解除页面，全清空会删除封禁记录。

## 销户和完整清理边界

销户先禁用账号并留住用户名/邮箱，然后由持久闭户队列驱动已有 task tombstone/source cleanup 和 knowledge cleanup。只有任务、知识文档、上传预留及存储对象清理完成才删除账号并释放身份。单次失败不宣称完成，租约到期可续跑；必须保持公共清理 worker 与私有闭户 worker 运行。

账号级清理保留必要操作审计；使用事件改成新的不可反查账号的统计 ID，清除维度，以保留流失用户的统计分母。不能称其为法律意义的匿名化证明。迟到写入防护记录可能按既有 cleanup guard 生命周期继续保留，以清理生产者遗留；完整全清空另行清掉所有表。

历史 student 或参与其他教师任务的账号，当前拒绝直接销户；不能通过角色更改绕过现有跨教师提交检测。后续需要单独设计参与者数据处置，避免破坏老师尚在运行的批改。

全清空详见 [ADMIN_RESET.md](ADMIN_RESET.md)：完整 ORM/数据库表比对，用户/业务/事件/审计/封禁全清；专用本地上传、历史存储根、业务 TMPDIR、孤立文件；对象版本、删除标记和 multipart。保留 schema/Alembic版本/基础设施/配置/密钥，外部维护目录仅保留无用户名邮箱的最小回执。未知表或遗漏存储后端使预览失败关闭，不只删 users。

所有公共、私有、后台、调度服务必须停止；共享服务锁/独占清理锁及 PostgreSQL advisory 锁阻止重叠。两种 ASGI 入口已持有维护锁覆盖启动到后台线程真正退出；配置维护目录的服务进程在最终 shutdown 等待默认 executor，不能在同一 event loop 重启 lifespan。独立 worker 也必须遵循该锁/停止契约。失败状态禁止启动服务，原计划可恢复；已经删除的对象不可回滚。范围变化要求新预览，成功后重复旧指令只返回旧回执，不删除重新注册的数据。

**当前运行限制**：仅允许 development/test + 显式开启 + 专用存储标记。生产环境执行能力的 code-only 开关请求被自动审批两次拒绝，尚未实现；本轮未执行任何真实环境清空。对象逻辑由假 S3 验证，网页不会隐式创建对象存储客户端，object 模式需在经授权的维护终端预览。

4. 管理员默认 API 地址 `/api`，`backend.private_main` 仅明确开关后启动；`/api/auth/*` 为允许的登录/刷新/退出/改密/重置端点，普通注册和旧邀请不挂载。`SMARTAI_ADMIN_DIST` 默认定位 `dist-admin`，有 `admin.html` 才提供 SPA；未知 `/api` 不回 HTML。公共 production app 不挂管理员路由/监控/清空预览，公共构建不包含管理页面。
5. 自管主机绑定 **127.0.0.1**，例如 `uvicorn backend.private_main:app --host 127.0.0.1 --port 8001 --no-access-log`。只能经 VPN/认证网关到私有站点。开关不是网络隔离；不要将管理 API 代理进公共域名。`backend/private-render.yaml` 改为 **pserv** 示例，不能视为 AWS 或网关配置已就绪；Render 类型依据官方 [Blueprint 规范](https://render.com/docs/blueprint-spec)。未执行 Render 配置变更。
6. 管理员推荐同源 HTML + `/api`，设置 `SMARTAI_ADMIN_FRONTEND_ORIGIN=https://实际私有站点`；两个后端都需要此设置，才能给管理员发送正确的忘记密码链接。`VITE_SMARTAI_ADMIN_URL` 是公共登录后的私有站点跳转，不共享 URL token；独立站点按自己的 Cookie 登录。HTTPS Cookie secure=true，同源 strict；若拆域，先核验精确 CORS、credentials、SameSite、浏览器第三方 Cookie 限制，不直接用通配。
7. 管理服务必须与公共服务共享同一个业务 DB、同一存储及必要密钥和邮件配置；仅仅加私有 API 服务而不给存储/worker 接线，会让销户持续等待。对象存储与主机挂载要单独做运维验收。访问日志应省略 query string，应用日志不记录 reset token/密码；管理 API 与邮件正文仅在隔离 sink 中测试。
8. 迁移后，通过 `python scripts/create_admin.py <username> --email <email>` 在私有维护终端交互首建；命令要求无管理员、身份未占用，不覆盖旧账号。后续授权在管理页面完成。清空后重复首建流程，不开启公开管理员注册。
