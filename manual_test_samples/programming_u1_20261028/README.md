## Mac本地复核

先人工阅读源码与来源，只在本包上运行。校验工具不是恶意代码沙箱，不能用于真实或任意学生源码；它不会导入SmarTAI、加载`.env`、访问数据库、调用模型、联网或计算成绩。

```bash
cd manual_test_samples/programming_u1_20261028
python validate_samples.py
python validate_samples.py --execute-constructed --output /tmp/u1-fixture-results.json
python -m pytest -q -c /dev/null --noconftest -p no:cacheprovider test_validate_samples.py
```

执行校验需要本机Python和C/C++工具链。Mac上通过`xcrun`定位已安装SDK，C使用C11、C++使用C++17；不会安装软件。已知正确的标准库程序先编译预检，环境失败不能满足“学生编译错误”预期。只解析、只编译和禁止执行的样例有独立策略及反例回归。判分表与本地结果的对应关系由静态数据核对，不从通过率生成建议分。

函数输入TXT保存位置参数数组，例如`[[-2,0,5]]`表示一个列表参数，预期TXT保存函数返回值。stdin输入和预期保存原始文本，含换行。本包对stdin按精确文本比较，而当前main会去首尾空白；本包更严格的约定须教师确认，不能把两者混称一致。

## 交接边界

教师确认题目合同、用例与逐条判分后，才能将确认范围交给实现同学作评分验收依据。先保存AI原建议，再填教师意见、最终分、角色/编号、日期和版本；构造来源永久保留。

当前main已有Python显式函数入口和stdin执行路径，但仍存在无预备用例时取首个`def`的分支、评分提示偏向通过率等待验收边界；C/C++在当前产品中未编译运行。本包Mac编译成功只说明样本自洽。U2负责原流程、真实模型质量和执行环境验收；07/08/09及新增实现仍由同学负责。本PR不改前端、后端核心或部署配置，不表示这些功能已交付。
